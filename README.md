# 课表换班采录台

从本地排课桌面软件导出的课节快照核定教室占用；从教师名单与委托回执裁定代课资格；从班级通知回执判定换班是否生效。教室、教师、通知分别有独立状态，任何一方不满足都会改变生效结论。原始导出字节和 SHA-256 保留在 SQLite，JSON 报告包含来源与逐项业务决定。

入口：`room-import`、`substitute-assign`、`notice-evaluate`，均为 `--db ledger.db export.json`。`substitute-withdraw` 会撤回代课并重开已生效通知，`notice-resend` 只在当前版本和冻结名单内补回漏送班级。正常与失败样例见 `tests/test_workflows.py`，涵盖跨日占用、容量、资质、并行教学、旧版通知与重试恢复。

`plan-reschedule` 对多门受扰课程联合匹配教室和教师：搜索时同时考虑当前房间占用、容量、教师资质与忙时，以及计划内互斥，优先最大化可安排课数，再降低偏好与空座成本。`approve-reschedule` 仅允许完整计划在当前版本经批准后生成新的房间与代课实体；批准时还会重新核对计划产生后新增的教室与教师占用，旧计划遇到资源变化会记录拒绝结论。这些实体随后可被通知系统使用。部分计划保留待协调状态，重放同一批准不会重复落地。

## 放学接领台

`pickup-import --db ledger.db pickup.json` 采录一个学生的一次放学窗口；`pickup-merge --db ledger.db east.json west.json` 合并多个离线出口。每个文件可包含 `students`、`guardians`、`contracts`（事先签定的接领方式）、`delegations`（临时委托的授权人、受托人、有效窗）、`revocations`、`sessions`、`credentials`（带序号的纸质移交凭证）和 `events`（离线动作）。

结论为 `允许交接`、`待核` 或 `应拒绝`。判定规则：

- **授权链**：登记监护人、合同签订时刻、合同/委托的适用学生与有效窗、撤销的签发与生效时刻。姓名相同不等于同一人，证件类型与号码才是身份；超范围转委托、先撤销后到场、合同签订晚于接领时刻都会被拒绝。合同若在会话中被锁定，不会因来人身份而改成更宽松的另一份。
- **当前放学窗口**：由当前生效课节的结束时刻和该班通知版次确定。`room-import` 更正下课时间后，旧的委托时窗与旧出口移交单不再当作现行放学交付，但旧单据保留在报告与 `entity_history` 中。
- **三次动作**：班级老师交出、出口值班员接收、实际来人接走必须各自成立且分属不同动作；单次扫码不构成交付。
- **出口与凭证**：每名学生每次放学仅预分配一个出口和一条带序号的纸质凭证。改出口须原出口双签交出、目标出口双签接收，且前一凭证作废。离线合并按凭证前后关系重建保管链；同序号出现互斥后继标为分叉并暂停安全交付结论，不按文件到达顺序选赢家。
- **事实与结论**：完整交付一旦发生就保留原记录；之后同票重放不会再生成一条放行，迟到撤销按其签发/生效时刻判断是否影响该次证明，不能抹掉已发生的交付。

报告逐学生列出授权链（含来源摘要）、有效课表与通知版次、出口凭证及其所有后继、证件核验、保管动作、分叉来源和放行/拒绝原因，并区分「已发生交付」与「当前可证结论」。同源异内容与同名不同证件会进入 `issue` 与待核结论。运行 `python -m pytest -q`。
